# 下のバーの同じタブをもう一度押す（reselect）— 2026-09-25

> 状態：実装済み。`feature/bottom-nav-reselect`（`feature/outliner-photo-rows` `d997e2a`の上）。merge前で停止。
> 人間の判断（2026-09-25）：YouTube等と同じく、いま表示中の下のバーの項目をもう一度押すと、そのタブの「ホームの位置」へ戻る。メモ＝ホーム一覧の先頭、カレンダー＝ページの先頭（月）、チャット＝チャットのホーム。機能凍結中の新しい振る舞いだが、人間がこの1件について明示的に指示した。

## 1. 監査（実装前）

- 下のバーは`MemoRippleApp`の`Scaffold.bottomBar`で、**3つのroot route（`MEMOS` / `CALENDAR` / `CHAT`）でだけ表示**される（チャットではキーボード表示中は隠れる）。Memo / Outliner / Noteの編集画面、ノート詳細、フォルダ以外の別route（アーカイブ・ゴミ箱・設定・日記一覧・日記の編集・チャットのステージ・チャット履歴）には**バーが無い**。したがって「エディタ・詳細では何もしない」は、ナビゲーションの構造そのものが保証している（押せるバーが無い）。
- それまでの同じタブの再タップ：`navigateTopLevel(route)`（`popUpTo(start){saveState}` ＋ `launchSingleTop` ＋ `restoreState`）がもう一度呼ばれるだけで、目に見える動きは無かった。
- メモのホーム：`MemoListScreen`に`HorizontalPager`（メモ / アウトライナー / ノート）。メモのページ（壁）は`cardsGridState`（staggered grid）と`shelfGridState`（「見出し」表示のgrid）をすでに画面側に持っていた。アウトライナーとノートのページは自分の`LazyListState`を内側で`remember`していた。**フォルダは同じ一覧の先頭の項目**（パンくずとフォルダの行）なので、「その一覧の先頭」はフォルダを変えない。
- カレンダー：`CalendarScreen`の1本の`LazyColumn`（配達のお知らせ → 月 → フィルタ → 月 / 日の記録）。状態を外に持っていなかった。
- チャット：タブの`ChatRoute`は「いまの会話」（`chat_last_conversation_id`）を表示する。ホーム＝会話の無い状態（ランチャー）。既存の「新しいチャット」（`ChatViewModel.newConversation()`）が、何も作らず・消さずに、会話の無い状態へ切り替える（会話は最初のメッセージで初めて作られる）。

## 2. 設計

- `ui/TabReselect.kt`：`TopLevelTab { MEMOS, CALENDAR, CHAT }`、`tabTap(shown, tapped)`（同じタブ → `RESELECT`、他 → `NAVIGATE`）、`TabReselectSignal`。
- **1回きりの出来事で、状態ではない**：`MutableSharedFlow(replay = 0, extraBufferCapacity = 1, DROP_OLDEST)`。聞いている画面にだけ届き、あとから作られた画面（構成変更・activityの作り直し・process death）には**再生されない**。誰も聞いていないタップは消える。保存しない（DataStore / SavedStateHandle / Roomのどれにも入らない）。1つの信号を`MemoRippleApplication.tabReselectSignal`に置き（メモリだけ）、`LocalTabReselect`でcompositionに渡す — routeの引数は変えない。
- バーは「同じタブか」だけを決める（`topLevelTabOf(currentRoute)`）。**一覧・スクロールの状態・タブの中のrouteは知らない**。各root画面が`OnTabReselect(tab) { … }`で自分のタブだけを聞き、自分の「先頭」を決める。
- 連打：`collectLatest` — 新しいタップは、まだ動いているスクロールを取り消してやり直す。重ならず、ナビゲーションも起きない（reselectは`navigate`を呼ばない）。
- スクロール：`scrollToTopOnReselect()`（`LazyListState` / `LazyGridState` / `LazyStaggeredGridState`）。すでに先頭（または空）なら何もしない。**画素で分かっている距離を1回だけ滑らかに**：先頭から1画面（またはそのページの`landing`）より遠ければ、まずちょうどその距離の位置へ瞬時に移り（`scrollToItem(0, 距離)`）、その距離を`animateScrollBy`の1回のease-out（360 ms）で戻り、最後に先頭へぴったり合わせる。§8を参照。

## 3. 各タブ

- **メモ**：いま見えているページの一覧**だけ**を先頭へ。壁 → `cardsGridState`（「見出し」表示なら`shelfGridState`）、アウトライナー → `outlinerListState`、ノート → `noteListState`（後の2つを壁の状態の隣へ持ち上げた）。変えない：選んでいるページ、フォルダ、検索・絞り込み・並び順・表示、他のページのスクロール位置。フォルダの中なら、そのフォルダの一覧の先頭（rootへは戻らない）。
- **カレンダー**：ページの先頭（月が見える位置）へ。変えない：表示中の月、選んだ日、すべて / 作成 / 更新、読み込んだ記録。日記一覧や日記の編集ではバーが無いので何も起きない（詳細を閉じない）。
- **チャット**：会話を開いていれば、チャットのホームへ（`ChatViewModel.goHome()` → `newConversation()`）。会話は削除しない、文字起こしは消さない、新しい会話は作らない — 履歴から元の会話をそのまま開ける。すでにホーム（会話・質問・答えの無い状態）なら何もしない。答えを作っている間・書き込みの間も何もしない（`newConversation`の既存の規則）。確認前のプレビューは「新しいチャット」と同じく消え、何も書かれない。ステージ（`CHAT_STAGE`）にはバーが無い。

## 8. カレンダーの「カク、カク」（2026-09-25、S26での指摘）

- **測った**（S20、debug build、`dumpsys gfxinfo framestats`、月の記録の一番下から再タップ）。最初の実装：16フレーム中4フレームが遅れ、90パーセンタイル150 ms。指で先頭まで弾いた場合は90パーセンタイル9 ms。
- **原因は2つ**：(1) `animateScrollToItem`は、まだ測っていない行の高さを知らないため、高さの違う行（月の格子・日付の見出し・記録）の上では段ごとに狙い直して止まる。(2) ページの先頭の**月の格子**（42マス。各マスにタップ・読み上げ・文字・点）は、見えなくなると捨てられ、戻るときに作り直される。作り直しがdebug buildで約100 msかかり、戻る動きの途中で1フレーム止まる。
- **直した**：(1) 動きは距離の分かった1回の`animateScrollBy`にした（§2）。(2) カレンダーは、先頭にいるときに月の格子の下端の位置を覚え、再タップでは**格子の最後の行がちょうど画面の上端にかかる位置**へ瞬時に移る（`landing`）。格子の作り直しは、何も動いていない瞬時の移動のフレームで済み、その後の滑らかな戻りは作り終えた行の上だけを通る。あわせて、格子の点を`Surface`から1つの丸（`background`）にした（見た目は同じ、部品が少ない）。途中で`LazyLayoutCacheWindow`（通り過ぎた行を作ったまま残す）も試したが、遠くへ瞬時に移ると格子は残らず、効かなかったので採らなかった。
- **結果**（同じ測り方、3回）：動いている間のフレームはすべて5〜16 ms。重い仕事は、タップの直後の最初の1フレーム（瞬時の移動、まだ何も動いていない）にまとまる — そのフレームには、画面が休んでいたときの起き上がり（測定上の約65 ms）も含まれる。release buildではさらに軽くなる見込み（未測定）。
