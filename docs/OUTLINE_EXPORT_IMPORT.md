|---|---|---|---|

## 2. 付随して見つかったこと

1. **写真が消える（既存の不具合、アウトラインに限らない）**：ポータブル読み込みは写真を`attachmentRepositoryFactory`が作る**別の`AttachmentRepository`**で取り込む。その`fileMutex`はアプリの`AttachmentRepository`の`fileMutex`と別物なのに、写真の置き場（`attachmentBlobStore`）は同じ。1枚目の写真の行が入ると、アプリの`attachmentObserver`が`garbageCollect()`（アプリ側のlock）を走らせ、その`cleanTemporaryFiles()`が取り込み中の2枚目の一時ファイルを消す → 2枚目は「取り込めなかった写真」として数えられる。写真2枚のアウトラインで**5回中4回、1枚が消えた**（メモでも同じ）。
2. **写真の位置**：どちらの経路も写真は本文の後ろの「## 写真」にまとめて書き出す。読み込みでは位置の情報が無く、メモの写真は先頭に、アウトラインの写真は（行の無い写真として）先頭の写真の行になる。**今のメモも同じ**で、写真の位置はポータブル書き出しでは運ばれていない。
3. **記号の正規化**：書き出しは見出しの記号（■など）を`#`に、タスクの記号を`- [ ]` / `- [x]`にする。意味（見出し・タスク）は保たれ、アウトライナーもそのまま読むが、記号そのものは変わりうる。
4. 題の無いアウトラインは「無題のメモ」という題で書き出され、読み込みで空の題に戻る（`PortableMemoParser`）。

## 5. 実装

### 5.1 写真が消える不具合 — lockは置き場のもの

**原因**（§2.1の再掲）：ポータブル読み込みは`attachmentRepositoryFactory`で**別の`AttachmentRepository`**を作り、そのrepositoryは自分の`fileMutex`を持っていた。写真の置き場（`attachmentBlobStore`）は同じ。取り込みの1枚目の行が入ると、アプリの`attachmentObserver` → `garbageCollect()`（アプリのrepositoryのlock）→ `blobStore.cleanTemporaryFiles()`が、取り込みが**まだ書いている**2枚目の一時ファイル（`attachments/tmp/`）を消した → その写真は「取り込めなかった」に数えられた。2つのlockは互いを知らないので、どちらも正しくlockを取っているのに排他になっていなかった。

**修正**：
- `AttachmentBlobStore.lock` — **その物理的な置き場（`attachments/`のcanonical path）に1つ**の`Mutex`（プロセス内の表で共有）。同じフォルダの上のstoreはすべて同じlockを持つ。
- `AttachmentRepository.fileMutex`は自分のlockを持たず、`blobStore.lock`を返すだけ。取り込み（picker / ポータブル）・コピー・削除・掃除・sweep（`garbageCollect`）・復元の取り付け（`installForRestore` / `installValidatedFiles`）はすべてこれを通る — repositoryがいくつあっても1つのlockの領域。
- `BackupEngine`のrepositoryを持たない経路（`attachmentRepository == null`の復元）も同じlockで写真を取り付け、Roomを書く（M_file → … → T、§16.100の順序のまま）。
- ポータブル書き出しのメタデータ除去のための一時コピーは、置き場の`tmp/`ではなく書き出し自身のcacheに作る（掃除はlockの中で`tmp/`を空にするので、lockを持たない書き出しがそこにファイルを置かない）。
- 取り込みを止める・待つ・やり直すといった特別扱いは無い。**rollbackの意味は元のまま**：1枚ずつ、blobと関係の行を1つのtransactionで入れ、失敗した写真は数えて（`skippedPhotos`）、その写真のblobが参照されていなければ消し、一時ファイルを掃除する — それがlockの中で起きるようになった。

## 9. 読み込みの言葉 — 「メモ」ではなく「ドキュメント」（2026-09-26、人間の決定）

S20で見つかった文言だけを、この回の中で直した。読み込みで入るのはメモとアウトライン（混ざることもある）なので、数えるものを**「ドキュメント」**と呼ぶ。種類ごとに文を分けない（混在でも正しい）。種類の判定・ポータブルの形・front matter・写真のlock・写真の行の位置・Room・Backup・読み込みの意味は変えていない。

| 場所 | 以前 | 以後 |
|---|---|---|
| Markdownを読み込む：確認の題 | 「N件のメモを読み込みますか？」 | **「N件のドキュメントを読み込みますか？」** |
| 同：確認の本文 | 「新しいメモとして追加します。今あるメモは変わりません。」（+タグの文） | 「新しいドキュメントとして追加します。今あるドキュメントは変わりません。」（タグの文はそのまま） |
| 同：何も無い | 「読み込めるメモがありませんでした」 | 「読み込めるドキュメントがありませんでした」 |
