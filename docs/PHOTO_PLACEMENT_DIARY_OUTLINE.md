## 1. 日記

### 1.1 今の形
- `diary_entries(id, diaryDateEpochDay, body, state, …)`。1日に複数件あり（Room 23〜）。写真は`diary_photo_attachments(id, diaryEntryId → CASCADE, blobSha256, sortOrder)`。同じエントリーに同じ写真は1回だけ（unique）、1件20枚まで。
- 画面：本文欄（`EditorTextField`、caretはViewModelに見えない、Undoなし、ツールバーなし）→ 写真のサムネイル列（キーボード表示中は隠れる）→ 未来の自分へ。写真を追加は下のバー。写真の追加は常に末尾、本文を先に保存しない。
- 本文を書く箇所：自動保存（`DiaryRepository.saveBody`）、AIの追記（`RepositoryDocumentAccess.appendToJournal`、本文全体を書き直す）、テンプレート（作成＋追記）、復元。FINALIZED / CORRECTING / LOCKED を新たに作る処理は今は無い（古い行と復元だけ）。
- 本文を読む箇所：カレンダー / 日記一覧の見出しと抜粋、過去の今日、検索、AI、読み上げ、未来日記（元の日記の本文を平文で表示）、書き出し（写真は本文の後ろにまとめる）。

### 1.2 案：メモと同じ仕組みを日記に
- **正本はblock、`diary_entries.body`はprojection**（空でない文章を改行1つでつなぐ）。書くのは新しい`DiaryContentStore`だけで、blockと同じtransactionで書く。写真の`sortOrder`はblock順にそろえる（Backup検証の0..n-1と並べ替えsheetがそのまま使える）。本文を読む箇所は**何も変えない**。
- 純関数は`MemoContent` / `MemoBlock`をそのまま使える（ストレージを知らない）。表と保存処理は日記用に別に作る（`memo_content_blocks`は`memos`と`memo_photo_attachments`を指しているため共用できない）。
- **Room 27**：`diary_content_blocks(id, diaryEntryId → diary_entries CASCADE, position, type, text?, photoAttachmentId? → diary_photo_attachments CASCADE, unique)`。変換では**各日記の本文を1つの文章、その後ろに写真**（今の見た目どおり）。既存の行は変えない。
- **Backup 21**：`diaryContentBlocks`。21のファイルは検証（日記に属する、写真行を1回ずつ、position 0..n-1、文章が1つ以上）、本文はblockから作り直す。1〜20のファイルは変換と同じく「本文→写真」で作る。
- **AIの追記と本文全体の書き込み**は`MemoContent.reconcile`で blockに載せる（末尾の追記は最後の文章へ）。
- **空の下書きの削除**：今は「本文が空で写真が無いDRAFT」。blockでは「projectionが空で写真blockが無い」。
- **LOCKEDの日**：今は画面の`isEditable`だけが守っている。blockの保存・写真の追加・並べ替え・結合を**保存処理の側でも断る**ようにする。
- **Drive**：`diary_content_blocks`を`DRIVE_DIRTY_TABLES`に加える。

### 1.3 編集画面
- メモの`MemoBlockColumn`を、日記でも使える形に広げる（いまは`MemoBodyEditor`とメモのツールバー前提）。日記はツールバーもUndoも無いので、文章欄は日記の今の見た目のまま、写真は大きく縦に、編集中は右上の⋮（フルスクリーン / 写真一覧 / 削除）、タップ・長押しなし。
- 写真を追加：先に本文を保存 → caretの位置で文章を分けて写真を入れる（メモと同じ`insertPhotos`）。caretを渡すため、日記の本文欄をViewModelが選択位置を知れる形にする。
- 写真がある日記では、キーボード表示中も写真を隠さない（メモと同じ）。「未来の自分へ」は列の下にそのまま置く。
- 閲覧（LOCKEDの日、読み上げ中）も同じ順番で写真を表示。

### 1.4 変えないもの
DRAFT / FINALIZED / CORRECTING / LOCKED の扱い、自動保存の間隔、1日に複数件、未来日記のすべての規則（未来日記の画面に写真は出さない — 今と同じ）、書き出しの写真の位置（本文の後ろ。メモと同じ既知の制限）。

### 1.5 テスト
変換（26→27を実ファイルで）、Backup 21の往復と1〜20の復元、検証の拒否、caretでの挿入、削除で文章が残る、LOCKEDで書けない、空の下書きの削除、AIの追記、検索、S20で既存の日記の変換と新しい「文章→写真→文章→写真」。

### 1.6 注意点（監査で見つけたこと）
- **ロックの順番**（**以前からある問題**、今回の変更とは別）：AIの追記は「transaction → 日記のロック」、復元は「日記のロック → transaction」の順で取る。同時に走ると互いに待ち合う可能性がある。blockの保存処理はどちらか一方の順に合わせる必要がある。別件として直すか、人間の判断を仰ぐ。
- 同じ写真は1件に1回だけ（unique）。2回目は「追加済み」として扱う（今と同じ）。

## 2. アウトライナー

### 2.1 今の形
- アウトラインは`memos.body`（kind = outline）のテキストだけ。1行＝1項目（字下げ、記号、本文）。項目のidは**読み込むたびに振り直す**もので、保存されない。安定した項目の識別子は無い（折りたたみは「深さ＋文字＋何回目か」のhashで、文字を直すと変わる）。
- **知らない行もそのまま残る**（`serialize(parse(t)) == t`、テスト済み）。
- 写真は`memo_photo_attachments`に入り、画面では一覧の上のサムネイル列。並べ替えは無い。閲覧モードに写真は出ない。

### 2.2 位置の持ち方の比較
- **別の表で項目に結びつける** → 結びつける先が無い（idは毎回変わり、文字のhashは文字を直すと変わる。行番号は「上に行を足すとずれる」ためメモで不採用になった方式）。**不採用。**
- **項目の行末に印を付ける**（`[Rn]`のように） → 写真がその行に付いて動くが、1行に写真が何枚も付くと行が読みにくく、分割・結合で印がどちらに付くかが曖昧。
- **写真を1行としてアウトラインに書く（推奨）** → 写真の行は字下げを持ち、項目と一緒に字下げ・移動・ドラッグ・折りたたみ・ズームされる。Undo / Redoはもともと文書全体の写しなので位置も戻る。表を足さないのでRoomは変わらない。

### 2.3 写真の行の書式（案）
```
  ![写真](photo:<sha256>)
```
- Markdownの画像の形。写真はそのアウトラインの写真行を**画像の中身のhash（sha256）**で指す。1つのメモに同じ写真は1回だけなので、hashで一意に決まる。DBのidを本文に書かないので、**復元・複製・ポータブル読み込みでidが変わっても壊れない**。AIに本文を渡すときも、DBのidがモデルに入らない。
- 写真の行が指す写真が無い（削除済みなど）→「写真が見つかりません」の行として表示し、長押しなどで消せる。写真の行が無い写真（今ある写真）は、今と同じく上にまとめて表示。**変換は要らない。**
- caretが行の途中なら、そこで項目を分けて（改行と同じ `split`）間に写真の行を同じ深さで入れる。行末なら次に、行頭なら前に入る。

### 2.4 本文を読む箇所の対応（全部必要）
| 箇所 | 対応 |
|---|---|
| アウトライナーの行 | 写真の行は大きな写真として描き、文字は編集させない。Backspace / 結合 / 分割 / テンプレート挿入で写真の行に文字が混ざらないようにする |
| 閲覧モード | 写真の行を写真として表示（`MemoReadingView`の`photoBreaks`を使う） |
| メモ一覧のカード・カレンダーの見出し | 写真の行を飛ばす |
| 読み上げ・コメントの流れ（本文モード）・検索 | 写真の行を除く |
| AI（本文を読む、追記のプレビュー） | 写真の行を除いて渡す |
| 書き出し（Markdown / DOCX / ポータブル） | 写真の行を写真ファイルへの参照に置き換える、または除く |
| 複製 | 本文と一緒に写真も複製する（今は写真を複製しない） |
| 分割表示の本文ペイン | 写真の行はそのまま文字で見える（編集はできる）。触らない |
| Backup | 写真の行が指すhashが、そのアウトラインの写真にあるかを検証。本文の書式に行の種類が増えるので、日記と合わせて**21**に含める |

### 2.5 変えないもの
アウトラインの書式の他の部分、`serialize(parse(t)) == t`、折りたたみ・ズームの保存先、AIの追記（末尾に項目を1つ）、コメントの`[Rn]`。
